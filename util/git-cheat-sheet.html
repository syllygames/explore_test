When things go wrong

Undo — find your situation first

I edited a file and want the old version backDiscards unstaged edits. Nothing recovers them.
I staged something too earlyUnstages it, edits untouched.
My last commit message is wrongOnly if you haven’t pushed it.
I forgot a file in the last commitFolds it in and keeps the existing message.
Undo the last commit, keep everything stagedThe commit disappears, the work stays ready to recommit.
Undo the last commit, keep the files onlyCommit and staging both undone; your files are as you left them.
Undo the last commit and throw the work awayDeletes the commit and the changes in your files.
Undo a commit I already pushedAdds a new commit that reverses the old one. Safe on shared branches.
I ran reset --hard and regret itLists every position HEAD has held. Find the sha, then git reset --hard <sha>. Works for roughly 90 days.
Wipe untracked junk out of the folderDry run — shows what would go. Swap -n for -f to actually delete.

Set up once, edit rarely

Ignore files

Save these patterns in a file named .gitignore at the root of the repo.

node_modules/A folder and everything in it, found anywhere in the tree.
*.logAny file with that extension.
/buildOnly at the repo root, not in subfolders.
!keep.logAn exception that rescues one file from a rule above.
secrets/*.envA pattern inside a specific folder.

.gitignore only affects files Git isn’t already tracking. Already committed it? Run git rm --cached <file> first.

The words Git assumes you know

Glossary

HEADThe commit you’re currently sitting on. HEAD~1 is its parent.
originThe default nickname for the remote you cloned from. Just a name.
mainThe conventional name of the primary branch. Nothing about it is special to Git.
SHAThe 40-character ID of a commit. The first 7 characters are enough to use.
trackedA file Git has been told to watch. Untracked files are invisible to commits.
upstreamThe remote branch yours is paired with, so bare push and pull know where to go.
detached HEADYou checked out a commit instead of a branch. New commits here belong to nothing — make a branch before working.
fast-forwardA merge with nothing to reconcile, so Git just slides the branch pointer forward.
